# Архитектура

`app.py` управляет окнами Tkinter, вкладками, сохранением, ссылками и отображением состояния плеера. Изменение текста вызывает автосохранение, обновление ссылок через 400 мс и подготовку речи через 500 мс. Вставка запускает подготовку без задержки. Настройка автоподготовки учитывается для всех способов изменения текста.

`NarrationEngine` из `narration.py` выполняет синтез в рабочих потоках и сообщает результаты через очередь. Tkinter читает очередь в главном потоке. Номера задач позволяют игнорировать устаревшие результаты после остановки и смены текста.

Для онлайн-голосов `streaming_audio.py` принимает MP3, декодирует его через PyAV в PCM на диске и передаёт звук через ограниченный буфер miniaudio. После завершения создаётся WAV. Голоса SAPI используют фрагменты из `audio_chunks.py`. Готовый WAV поддерживает скорость и перемотку через WMP.

`speech_text.py` находит ссылки и готовит произносимый текст. `karaoke.py` сопоставляет слова с временными метками. Караоке — отдельный вид поверх редактора; исходный текст остаётся в редакторе активной вкладки.

Кнопки текста каждый раз определяют активную вкладку. Вставка из кнопки и виртуального события `<<Paste>>` использует один обработчик. Он читает буфер до изменения текста и возвращает `break`, чтобы стандартная привязка Tk не вставила текст второй раз. Для Windows сочетания Ctrl определяются по виртуальным кодам клавиш. Копирование кнопкой берёт весь исходный текст, копирование клавишами — выделение.

Сервер, собственный HTTP API и SQL-база отсутствуют.
